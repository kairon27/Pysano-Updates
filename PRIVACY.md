# Pysano privacy notice

Policy version: 2026-10-31. Local Beta 30 adds the credential component described below. Version scope: existing public versions through Beta 23 and experimental Beta 26, including the intervening Beta 24/25 candidate changes. Beta 26 includes a user-declaration gate; versions through Beta 23 do not. Maintainer/publisher account: [kairon27](https://github.com/kairon27). This notice describes the app's current technical behavior; it does not claim Google, GitHub or Hugging Face follow the same retention policy as Pysano.

## Processing on your Mac

Pysano processes microphone audio, recognized text, selected editor text and configured vocabulary to provide features you request. Accessibility captures the target app/editor, available value and selection to prevent pasting into a changed field. Input Monitoring detects configured shortcuts. These permissions do not authorize continuous audio capture or publishing messages.

Local dictation and local previews process audio on the Mac once models are downloaded. Phrase substitutions and settings are stored locally. Optional cloud actions, cloud preview speech and Auto-mode cloud routes remain cloud operations even when a local model is installed.

Optional dictation proofreading sends recognized text to the selected local Qwen, Gemma or Lapa worker before insertion. If the worker fails, times out or returns an invalid result, Pysano inserts the original recognized text. Phrase substitutions apply after proofreading. The worker has network access denied.

When a command finds no selected text, Pysano offers an explicit screen-area capture. An optional setting opens the area selector immediately when a command finds no selection; it is off by default. macOS screen-capture permission is required. The image model can be changed before submission. Qwen3.5 4B, 9B, 27B and Gemma 4 E4B use separately downloaded vision components and process the image and question on the Mac. If Gemini is selected for images, the selected area and question are sent to Google using the configured Gemini API key. There is no automatic switch between these routes. Voice questions for local image models require local speech recognition. Gemini voice questions follow the dictation speech-model setting. Written instructions for text and screenshots do not use the microphone or speech recognition.

The captured area stays in memory between capture and the question, then with the answer until that answer is dismissed, copied, replaced by another operation, or cleared by session lock/sleep. The answer includes a thumbnail and an in-app image viewer; previewing does not export a file or launch an external viewer. Screen capture and local inference use user-only temporary directories under the macOS temporary folder, `Pysano-Screenshots/<UUID>/`, removed when their operations finish or are canceled. An app or system crash can leave temporary files. On launch Pysano removes only its UUID screenshot workspaces older than 24 hours; files from older versions outside this folder remain subject to macOS temporary-file cleanup. Screenshot questions are displayed for review and copying. They are not added to dictation recovery history. Written instructions are kept in memory until completion or dismissal. A failed written command and its source context remain in memory for explicit Retry or Discard; they are not saved for recovery after an app restart.

Temporary follow-up chats keep the original selection or screenshot, user questions and successful answers in memory. Follow-ups use the model chosen for the first answer, without automatically switching to a cloud model. Cloud chats resend their source, image when present, and successful history to Gemini on every follow-up, using `store: false` without server conversation IDs. Local chat workers have network access denied. Closing or copying/replacing the answer, session lock/sleep, or quitting clears the chat. Follow-up drafts, turns and audio are not added to Recovery or meeting archives. The first text command still follows the ordinary latest-transcript recovery policy described below. Context is bounded by the model budget and eight question/answer exchanges; a full context produces a notice without dropping earlier turns.

Voice follow-ups use the current dictation speech model, shown next to the microphone controls. For a local screenshot chat, speech recognition must also be local. Other local text chats can use the configured cloud speech recognizer when explicitly selected. Voice follow-ups use a user-only temporary WAV, removed when recording stops or is canceled, with no durable retry backup; a crash can leave temporary audio for macOS cleanup.

The quick translation command and optional double-⌘C shortcut translate the active text selection, or immediately open region capture when no selection is available. Text and image translation have independent source/target language defaults. Text translation uses its independently selected text model; screen translation uses the selected image model. Local workers run with network access denied. A cloud selection sends the text or captured image and translation instruction to Google Gemini. Changing the target language in the result reuses the original in-memory material. Closing the temporary chat releases the image and conversation. Removing a text/image model deletes its local weights, dependent vision component and partial downloads; removing only its vision component preserves the text weights. This does not delete notes, transcripts or settings.

The Gemini key is stored in the login Keychain and held in app memory while needed. It is sent directly to Google to authenticate requests, not to a Pysano server. Session lock/sleep handling clears the in-memory credential session. Starting with local Beta 30, a fixed signed credential component accesses a separate Pysano Keychain entry. The app verifies its exact binary hash and signing certificate; the component verifies the calling Pysano application identifier and certificate. Key data travels only through private process pipes; the component has network access denied. Ordinary app builds reuse the component unchanged. Repair key access can request a one-time macOS authorization to copy the legacy key into this entry and verifies the copy. The legacy entry is retained unchanged for recovery. Explicit Delete key removes both entries; it reports a failure if either deletion fails. Saving a new or replacement key updates the component-owned entry. A changed component or signing identity requires a separately reviewed migration; a locked login Keychain can still require macOS authentication.

## Recovery and deletion

Pysano preserves the latest completed dictation transcript in `~/Library/Application Support/Pysano/Recovery/latest-transcript.json`. A failed/interrupted recording can be preserved as `pending-dictation.wav` for Retry. These files are restricted to the macOS user (files 0600, directory 0700), but are not separately encrypted by Pysano. They may be included in your backups. The latest text persists until replaced or cleared; a pending recording persists until successful recognition or explicit discard.

If automatic insertion cannot be confirmed, a separate recovery copy is saved in `Recovery/Undelivered` with the same file permissions. Later dictation does not overwrite these copies. Review them under **Latest text → Unconfirmed insertions**, check the destination field, and use **Mark as recovered** to remove a copy. Pysano does not automatically retry an ambiguous insertion, because it might duplicate text that arrived late.

Use **Latest text → Clear** to remove the saved transcript, **Discard failed recording** to remove a pending recording, **Connection → Delete key** to remove the local Keychain key, and **Delete** on a local model card to remove downloaded weights. Removing the local key does not revoke it at Google. Uninstalling only the app bundle does not remove settings, models, Keychain entries or recovery files.

In Notes, **⋯ → Move to Trash** asks for confirmation and moves the complete recording folder, including audio, transcript, summary and working files, to the macOS Trash. It is unavailable while notes are recording or processing. There is no permanent-deletion fallback if Trash fails. Exported copies outside the recording folder are kept. Restore the UUID folder from Trash to its original `Pysano/Meetings/` location and reopen Notes to reload it. Emptying the macOS Trash permanently removes those files and is controlled by macOS and the user.

Normal Live Translation keeps audio buffers and displayed translations in memory, without a Pysano audio/transcript archive. macOS logs can contain operational errors and app/device identity; Pysano's focus diagnostics omit field values, selected text, key values, keystrokes and clipboard contents. Do not assume arbitrary support screenshots or exported logs contain no private information.

## Meeting notes (Beta 26)

When explicitly started, Meeting notes records the selected microphone and optional application's audio to `~/Library/Application Support/Pysano/Meetings/<UUID>/`. Local PCM journals, metadata and completed transcript segments persist until the user removes them, including after interruption. Files use user-only permissions and are not separately encrypted; backups can contain them. Closing the settings window does not stop recording. Stop explicitly in the page/menu; sleep and capture failures interrupt capture without silently restarting it.

Recognition can use an installed local model or an explicitly selected Gemini cloud profile. Local selection keeps recognition offline. Cloud transcription sends the saved audio in bounded chunks to Google using the existing Gemini API key, with store=false and no provider conversation IDs. Recording itself is local and does not transmit audio until transcription is explicitly started. Cloud summaries send the saved transcript, instructions and partial summaries to Google, not the recording audio. They use the same source-reference validation as local summaries. User-managed profiles contain a display name, model ID and task type, never a separate API key. Removing a profile does not remove recordings or earlier results. Changing a model invalidates its partial-work cache. Missing keys, consent, model access or quota produce an error without automatic local/cloud fallback. Me / Other participants identify recording channels, not verified speaker identities. Local Beta 31 offers microphone-only, selected-application audio, or all Mac playback. Setup displays the scope before recording and remembers an explicitly chosen source. Starting with local Beta 33, a recording with application or system audio prepares both channels but starts with Pysano microphone capture off. The recording button, menu or dictation shortcut can turn it on and off; this does not mute the microphone in another application or call. Pysano stops its input capture while off and writes silence to keep the timeline aligned. Microphone-only notes start with the microphone on. There is no automatic echo cancellation or speaker-based switching. All Mac playback includes other applications. The two channels are saved separately; channel names and signal-detection metadata are retained with the session. Audio level indicators do not identify people. Existing single-channel recordings are not relabeled as if speaker identity had been detected. Beta 26 adds optional local AI summaries using separately downloaded Qwen, Gemma or Lapa weights. The llama.cpp worker receives transcript text through stdin, has network access denied, and exits after each generation. There is no cloud fallback. Generated summaries, source quotes and resumable intermediate parts remain in the meeting folder until removed. Summary text is an AI draft that needs review. Markdown exports contain the transcript and, when generated, the summary with its processing location and model. WAV/Markdown exports are additional local files with new names. Use Show saved files to review/remove a session in Finder. Uninstalling the app does not remove these files. The initial recording limit is four hours; audio uses about 115 MB per hour per channel, with additional space for exports.

## Google Gemini

Standard cloud dictation sends audio after recording. Live dictation and translation stream audio while active. Gemini selected-text actions and double-⌘C translation send the selected text and instruction. When a local model is selected for voice actions, the selected text and recognized instruction are processed by an offline worker on the Mac, and the preview uses the macOS voice for playback. Voice recognition still follows the dictation model setting. Cloud text-to-speech sends the preview text. Configured vocabulary and instructions can accompany applicable requests. Cloud usage requires an internet connection and may incur Google API charges.

Long or recovered dictation can upload audio to Google's Files API. Pysano requests deletion after recognition; deletion may fail during an interruption. Google documents automatic Files API deletion after 48 hours. `store=false` on Interactions does not override Google's terms, safety logging, temporary file retention or data-processing rules. Cancelling cannot recall data already transmitted.

Under [Google's current Gemini terms](https://ai.google.dev/gemini-api/terms), Unpaid Services may use submitted content and responses to improve products, with human review. Do not submit sensitive, confidential or personal information to Unpaid Services. Paid Services have different data-use terms, including limited safety/abuse logging. Pysano does not independently verify your Google billing tier, region or contractual eligibility.

## Other network recipients

Google receives authenticated requests and normal connection metadata. Model downloads connect to Hugging Face and its delivery infrastructure; GitHub hosts update archives and the feed. These providers can receive IP addresses and connection/request metadata under their own policies. Automatic update checks can be disabled under Updates. Beta 26 explicitly disables Sparkle system-profile submission and does not include an advertising or analytics SDK of its own.

## Rights, questions and changes

Submit a general question or a request for a private contact channel through [GitHub Issues](https://github.com/kairon27/Pysano-Updates/issues). Do not put private data into a public issue. There is currently no dedicated private support inbox advertised by this project. Do not submit sensitive material until a suitable private channel is agreed.

Applicable privacy rights and publisher-identification obligations depend on where the product is offered and on the actual processing relationship. This technical notice does not certify compliance in every jurisdiction. Before an unrestricted commercial/international rollout, the maintainer must review the required legal identification/contact details and applicable obligations. Material changes to cloud disclosures require a new in-app acknowledgement.
