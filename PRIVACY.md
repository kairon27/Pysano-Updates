# Pysano privacy notice

Policy version: 2026-10-31. Local Beta 30 adds the credential component described below. Version scope: existing public versions through Beta 23 and experimental Beta 26, including the intervening Beta 24/25 candidate changes. Beta 26 includes a user-declaration gate; versions through Beta 23 do not. Maintainer/publisher account: [kairon27](https://github.com/kairon27). This notice describes the app's current technical behavior; it does not claim Google, GitHub or Hugging Face follow the same retention policy as Pysano.

## Processing on your Mac

Pysano processes microphone audio, recognized text, selected editor text and configured vocabulary to provide features you request. Accessibility captures the target app/editor, available value and selection to prevent pasting into a changed field. Input Monitoring detects configured shortcuts. These permissions do not authorize continuous audio capture or publishing messages.

Local dictation and local previews process audio on the Mac once models are downloaded. Phrase substitutions and settings are stored locally. Optional cloud actions, cloud preview speech and Auto-mode cloud routes remain cloud operations even when a local model is installed.

The Gemini key is stored in the login Keychain and held in app memory while needed. It is sent directly to Google to authenticate requests, not to a Pysano server. Session lock/sleep handling clears the in-memory credential session. Starting with local Beta 30, a fixed signed credential component accesses a separate Pysano Keychain entry. The app verifies its exact binary hash and signing certificate; the component verifies the calling Pysano application identifier and certificate. Key data travels only through private process pipes; the component has network access denied. Ordinary app builds reuse the component unchanged. Repair key access can request a one-time macOS authorization to copy the legacy key into this entry and verifies the copy. The legacy entry is retained unchanged for recovery. Explicit Delete key removes both entries; it reports a failure if either deletion fails. Saving a new or replacement key updates the component-owned entry. A changed component or signing identity requires a separately reviewed migration; a locked login Keychain can still require macOS authentication.

## Recovery and deletion

Pysano preserves the latest completed dictation transcript in `~/Library/Application Support/Pysano/Recovery/latest-transcript.json`. A failed/interrupted recording can be preserved as `pending-dictation.wav` for Retry. These files are restricted to the macOS user (files 0600, directory 0700), but are not separately encrypted by Pysano. They may be included in your backups. The latest text persists until replaced or cleared; a pending recording persists until successful recognition or explicit discard.

If automatic insertion cannot be confirmed, a separate recovery copy is saved in `Recovery/Undelivered` with the same file permissions. Later dictation does not overwrite these copies. Review them under **Latest text → Unconfirmed insertions**, check the destination field, and use **Mark as recovered** to remove a copy. Pysano does not automatically retry an ambiguous insertion, because it might duplicate text that arrived late.

Use **Latest text → Clear** to remove the saved transcript, **Discard failed recording** to remove a pending recording, **Connection → Delete key** to remove the local Keychain key, and **Delete** on a local model card to remove downloaded weights. Removing the local key does not revoke it at Google. Uninstalling only the app bundle does not remove settings, models, Keychain entries or recovery files.

Normal Live Translation keeps audio buffers and displayed translations in memory, without a Pysano audio/transcript archive. macOS logs can contain operational errors and app/device identity; Pysano's focus diagnostics omit field values, selected text, key values, keystrokes and clipboard contents. Do not assume arbitrary support screenshots or exported logs contain no private information.

## Meeting notes (Beta 26)

When explicitly started, Meeting notes records the selected microphone and optional application's audio to `~/Library/Application Support/Pysano/Meetings/<UUID>/`. Local PCM journals, metadata and completed transcript segments persist until the user removes them, including after interruption. Files use user-only permissions and are not separately encrypted; backups can contain them. Closing the settings window does not stop recording. Stop explicitly in the page/menu; sleep and capture failures interrupt capture without silently restarting it.

Recognition uses an installed local model. No notes audio or transcript is sent to Gemini. Me / Other participants identify recording channels, not verified speaker identities. Local Beta 31 offers microphone-only, selected-application audio, or all Mac playback. Setup displays the scope before recording and remembers an explicitly chosen source. Starting with local Beta 33, a recording with application or system audio prepares both channels but starts with Pysano microphone capture off. The recording button, menu or dictation shortcut can turn it on and off; this does not mute the microphone in another application or call. Pysano stops its input capture while off and writes silence to keep the timeline aligned. Microphone-only notes start with the microphone on. There is no automatic echo cancellation or speaker-based switching. All Mac playback includes other applications. The two channels are saved separately; channel names and signal-detection metadata are retained with the session. Audio level indicators do not identify people. Existing single-channel recordings are not relabeled as if speaker identity had been detected. Beta 26 adds optional local AI summaries using separately downloaded Qwen, Gemma or Lapa weights. The llama.cpp worker receives transcript text through stdin, has network access denied, and exits after each generation. There is no cloud fallback. Generated summaries, source quotes and resumable intermediate parts remain in the meeting folder until removed. Summary text is an AI draft that needs review. Markdown exports contain the transcript and, when generated, the local summary. WAV/Markdown exports are additional local files with new names. Use Show saved files to review/remove a session in Finder. Uninstalling the app does not remove these files. The initial recording limit is four hours; audio uses about 115 MB per hour per channel, with additional space for exports.

## Google Gemini

Standard cloud dictation sends audio after recording. Live dictation/translation streams audio while active. Selected-text actions send the selected text and instruction. Cloud text-to-speech sends the preview text. Configured vocabulary and instructions can accompany applicable requests. Cloud usage requires an internet connection and may incur Google API charges.

Long or recovered dictation can upload audio to Google's Files API. Pysano requests deletion after recognition; deletion may fail during an interruption. Google documents automatic Files API deletion after 48 hours. `store=false` on Interactions does not override Google's terms, safety logging, temporary file retention or data-processing rules. Cancelling cannot recall data already transmitted.

Under [Google's current Gemini terms](https://ai.google.dev/gemini-api/terms), Unpaid Services may use submitted content and responses to improve products, with human review. Do not submit sensitive, confidential or personal information to Unpaid Services. Paid Services have different data-use terms, including limited safety/abuse logging. Pysano does not independently verify your Google billing tier, region or contractual eligibility.

## Other network recipients

Google receives authenticated requests and normal connection metadata. Model downloads connect to Hugging Face and its delivery infrastructure; GitHub hosts update archives and the feed. These providers can receive IP addresses and connection/request metadata under their own policies. Automatic update checks can be disabled under Updates. Beta 26 explicitly disables Sparkle system-profile submission and does not include an advertising or analytics SDK of its own.

## Rights, questions and changes

Submit a general question or a request for a private contact channel through [GitHub Issues](https://github.com/kairon27/Pysano-Updates/issues). Do not put private data into a public issue. There is currently no dedicated private support inbox advertised by this project. Do not submit sensitive material until a suitable private channel is agreed.

Applicable privacy rights and publisher-identification obligations depend on where the product is offered and on the actual processing relationship. This technical notice does not certify compliance in every jurisdiction. Before an unrestricted commercial/international rollout, the maintainer must review the required legal identification/contact details and applicable obligations. Material changes to cloud disclosures require a new in-app acknowledgement.
