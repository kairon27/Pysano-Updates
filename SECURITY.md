# Security reporting

Never post API keys, passwords, private keys, recordings, private transcripts or exploit details in public Issues.

If GitHub displays **Security → Report a vulnerability** for this repository, use that private reporting mechanism. Its availability depends on repository settings; this document does not claim it is currently enabled. Otherwise open a minimal public issue asking the maintainer to arrange a private channel, without exploit details or personal data, and wait before sharing sensitive material.

The maintainer account is kairon27. There is no dedicated private security email currently advertised. There is no guaranteed response time or bounty program.

Updates use Sparkle archive signatures and HTTPS. A public certificate or SUPublicEDKey is not a private key. Do not disable Gatekeeper, SIP, signature verification or system-wide security protections as a troubleshooting step. A valid archive signature proves origin/integrity, not absence of vulnerabilities or full compliance.
